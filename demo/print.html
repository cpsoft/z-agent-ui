打印

组件不感知打印 —— 没有一个组件知道 @media print 的存在。 它们照常渲染，z-print 在按下打印的那一刻，把渲染完的那棵子树拍成快照， 在独立文档里用自己的排版规则印出来。

所以新增组件不需要另写打印样式，也不会出现「这个组件印得好、那个把分页器也印出来」。

一份能直接交出去的报表

下面这段是真表格，46 行 × 6 列，A4 上会分成 2 页。点「打印」看纸面效果，或按 Ctrl/Cmd + P。

打印 页码：仅当前页 页码：不要 恢复 1 / 3 页眉每页重复 · 表头每页重复 · 复选框与分页器不印

快照里发生了什么

四步，全部发生在按下打印的那一瞬间。

步骤做法为什么不能换别的写法
1. 展开 shadow 遍历子树，把每个元素的 shadow root 摊平，<slot> 换成真正分到这里的节点 shadow 里的样式外部改不了 —— 想让表格不印分页器，只能把内容取出来自己排
2. 收齐样式 取每个自定义元素的 static styles，把 :host 改写成标签名 摊平之后没有 shadow 可指；不改写的话组件根样式（display: block 等）全部失效
3. 固化令牌 从样式表读浅色主题的 --z-* 值写进快照 纸永远是白的。宿主此刻可能是暗色主题，拿暗色令牌印出来就是一整页墨
4. 进 iframe 打印 写进一个屏幕外的 iframe，等字体与图片就位，调 contentWindow.print()； 页眉页脚与页码由快照里的 @page margin box 画 iframe 里没有屏幕上的其它元素 —— 天然只印这一块，宿主不必写 body > :not(z-print)

宿主只需要包一层

没有要补的 CSS、没有要加的类、没有要注册的样式表。

import "z-agent-ui/app/print";
import "z-agent-ui/report/table";

<z-print id="sheet" title="门店月度销售报表" footer="内部资料">
  <z-report-table lines></z-report-table>
</z-print>

// 触发打印（要先改数据就监听 z-before-print，改完放行）
document.getElementById("sheet").print();

// 或者只要那份快照，自己走别的通道（服务端出 PDF / Electron / 小程序端）
const html = document.getElementById("sheet").snapshot();

印出来是什么样

快照里的规则只认标签（table / thead / tr / button）， 不认任何组件内部类名 —— 所以任何组件渲染出的真表格都自动获得同样的待遇。

纸面上的规则实现说明
表头每页重复thead { display: table-header-group } 写 position: fixed 只会在第 1 页出现；写 table-row-group 则完全不重复
合计行每页重复tfoot { display: table-footer-group } 多页报表最后一页才有合计，翻页时看不到基准
行不跨页断tr { break-inside: avoid } 一行数据被纸张拦腰截断会读成两行
页眉页脚每页重复@page 的 @top-left / @bottom-left 别用 position: fixed：打印时它相对内容区而不是纸张，会压住正文第一块内容。 代价是页眉只能是文本（margin box 放不了 logo 和多列布局）
页码@page { @bottom-right { content: counter(page) " / " counter(pages) } } counter(page) 只在 margin box 里有效，普通元素读不到
交互控件不印button / input / select / textarea 隐藏 纸上点了没用。默认按标签名隐藏（button / input / select / textarea）；要保留就关掉 hide-interactive

两处做不到：① 纸张尺寸由打印驱动或宿主的 @page 决定， 快照里的 @page size 不改变实际纸张（浏览器会忽略它），所以没有 paper 属性； ② 甘特图是虚拟滚动的，DOM 里只有当前可见那几十行 —— 快照也只能拍到这些，不承诺印全项目。
