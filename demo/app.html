L2 应用件

应用壳、应用切换、详情表单、登录。它们是「一个后台长什么样」的最小集合 —— 装配关系本身就是这一域的模型。

下面这一块可以真的操作

画框里是真实运行的整页 demo：滚动、点击、打开弹层都生效，主题与密度跟随上面的切换。 想全屏试，点右上角「单独打开」。

这一域有哪些件

取自 src/app/：

App switcher

后台顶栏的品牌名 + 下拉：在多套系统之间跳。当前项置灰，点当前项不派发事件。

点品牌名展开菜单；点「数据看板」不会有反应（那是当前应用）。

Show Code 
const el = document.querySelector("z-app-switcher");
el.label = "好用得";
el.apps = [                       // Array 属性（attribute: false），必须用 property
  { app: "dashboard", name: "数据看板" },
  { app: "etl", name: "数据集成" },
];
el.current = "dashboard";         // 当前项置灰，点击不派发

el.addEventListener("z-switch", (e) => {
  location.href = e.detail.item.url;   // 跳转由宿主决定
});

App nav

侧栏导航：吃「有哪些页面」，出分组菜单 + 选中态 + 折叠。不路由、不判权限、不记选中态。

收起

点条目会派发 z-navigate；「权限总览」是灰条（disabled，点了不派发）； 「未知图标」演示图标名不认识时回落标题首字。

Show Code 
const el = document.querySelector("z-app-nav");
el.items = registry.list(can).map((d) => ({     // 权限裁剪归注册表，组件不判
  path: d.path, title: d.title,
  group: d.meta?.group, icon: d.meta?.icon, order: d.meta?.order,
}));
el.active = engine.current;                     // 只读输入：后退/前进时高亮跟着地址走

el.addEventListener("z-navigate", (e) => {
  engine.go(e.detail.path);                     // 路由归 L4，组件不碰 history
  el.active = e.detail.path;                    // 宿主回灌，组件不自己记
});

Detail form

一屏就是一个表单：字段结构由 fields 数组给（含分组、必填、下拉选项）。 小屏自动单列，span 让一个字段跨整行。

改任一字段会发 z-change；点保存发 z-submit。

Property panel

属性面板：z-property-group 分组、z-property-row 一行「标签 + 控件」。 控件由使用者放进 row 的默认 slot —— 面板不猜下面该编辑什么。
