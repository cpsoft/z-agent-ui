在 React 里用

库自带一层极薄的 React 包装：src/react/index.ts 里 — 个 createReactWrapper(tag)。它只做三件事 —— 标签转 JSX、props 落到 attribute/property、 z-click 这类事件转成 onZClick 回调。

它不做第四件事：注册元素。包装层只 import { createReactWrapper }， 一个组件都不引 —— 所以引了包装还得引组件入口，这条下面单独说。

三行用起来

样式与组件入口各引一次，然后当普通组件写。包装层的导出名是 Z + PascalCase + React。

// ① 样式 + 组件入口（注册 z-button）② 包装层
import "z-agent-ui/z-agent-ui.css";
import "z-agent-ui/components/button";
import { ZButtonReact } from "z-agent-ui/react";

export function Save() {
  return (
    <ZButtonReact variant="primary" onZClick={() => save()}>
      保存
    </ZButtonReact>
  );
}

活的一个

下面这块是真 React 渲染的（react-dom/client 挂到本页），点按钮能加计数 —— 说明 onZClick 这条映射在真实 React 里是通的，不是纸上示意。

React 正在加载…

命名规则

规则只有一条：tag 的每段首字母大写 + 前后缀。m- 前缀变成 M， 中间的连字符变成下一个词的首字母。

元素导出名说明
z-buttonZButtonReact最常见形态
z-grid-colZGridColReact多段连字符逐段大写
m-action-barZMActionBarReact移动端 m- 也有包装，前缀统一带 Z
z-portal / z-position—L0 内部原语，不直接对外用，因此不提供包装

props 怎么落到元素上

React 的属性名是 camelCase，自定义元素认的是 kebab attribute，中间这层由包装做。 四条规则按值的类型分，读一遍能避开全部常见坑。

React 里写落到元素上为什么
buttonType="submit"button-type="submit"camelCase → kebab，逐个单词小写
loading={true} / {false}loading 空属性 / 移除布尔 attribute 的存在即真；写 "false" 在 HTML 里也是真，所以 false 只能靠删除
items={[...]} / columns={[...]}元素上的 property对象和数组传不进 attribute（会被 String() 变成 [object Object]），走 property 赋值
placeholder={undefined}移除该 attribute「显式置空」必须真的把旧值删掉，否则同位置复用实例时旧形态会残留

第四条最容易忽略：React 按「同位置同类型」复用实例，元素不重建， 上一种形态的 disabled / placeholder 会留在元素上，且不报错 —— 表现为「界面没更新」。包装层会先清理「上次有、这次没有」的键。

事件：z-click → onZClick

自定义事件名整体转成 on + PascalCase，z-select-close 就是 onZSelectClose。

// z-change → onZChange；detail 在 e.detail 里
<ZSelectReact
  value={value}
  onZChange={(e) => setValue((e as CustomEvent).detail.value)}
/>

两个细节：监听器只在挂载时挂一次，回调通过 ref 取最新闭包 —— 避免每次渲染重新绑定引起的 shadow DOM 重渲染（表现为闪屏）。 另外包装只响应元素自己发出的事件（e.target === el）， 子组件冒泡上来的同名事件不算 —— 否则 z-modal 里关掉一个 z-alert 会把整个弹窗一起关掉。

ref 拿到的是元素本体

不是包装组件，是那个自定义元素 —— 可以读属性、调方法、量尺寸。

const ref = useRef<HTMLElement>(null);

<ZTableReact ref={ref} columns={cols} data={rows} />

// ref.current 就是 <z-table>，属性和方法都在上面

三个坑，都是「不报错」的那种

现象原因怎么确认
标签在 DOM 里，但样式全无、内容消失 元素没注册：只引了 z-agent-ui/react（或只引了根入口 z-agent-ui） DevTools 里那个标签显示为 inline；补 import "z-agent-ui/components/xxx" 即好
改了 prop，界面上是旧值 复杂类型（数组/对象）当 attribute 传了，被 String() 拍平 看元素上有没有 [object Object]
事件回调不进 React 事件名拼错（onZclick / onClick），包装认的是 on + 大写开头 按 tag 的事件名 → on + PascalCase 转一遍

SSR：包装只是 React.createElement(tag)，服务端渲染出来就是那个标签， 注册发生在客户端 import 组件入口时 —— 所以服务端不需要 DOM，但客户端一定要引组件入口。
